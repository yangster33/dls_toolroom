FILLING THE UPPER LEFT

空着，还是
放一句话进去？

符号的重量现在压在右下（山）和右上（信号），左上象限 x 8–44 / y 8–50 几乎全空。 这不一定是错误——留白本身能托住山峰的上升感；但如果你想补，补的东西最好 不是装饰，而是第二层信息：测量、链路、距离、方位。

READING / 判断标准 1. 不加第三种语义，最好还是「山 / 信号 / 图纸」的延伸。
2. 32 px 下不糊成噪点，或允许在该尺寸隐藏。
3. 与右侧字标同处一行时，不把视线往左拉走。
4. 深色蓝图模式下不需要换一套几何。
ACONTROL

现状 / 什么都不加

左上留白让山脊的斜线和信号弧各占一个方向，读起来干净。缺点是缩到 32 px 时， 右侧信号弧成为唯一高点，重心有点偏。

BWIND / 已有试验

风线 / 从左上吹向信号

三条平行线，端头 270° 卷梢。语义上把「山」扩成「山 + 大气」，也暗示无线传播的介质。 视觉最满，但最容易读成天气图标；32 px 下建议整组隐藏。

x 9–37 / y 24–41 · stroke 2.4 · round cap
CDATUM / 推荐

标高线 / 把站点轴延长

从塔顶黄点向左拉一条虚线，端头一条测量短竖。它不新增语义，只是把「制图基准线」 从底边搬到信号高度：左有标高，右有覆盖弧，下面有地平线，三根横线自成秩序。 视觉最轻，却把空的地方「框」住了。

y 34.7 · x 12–42 · dash 3 / 3.2 · 端竖 11
DLINK / 推荐

链路 / 远端节点指向本站

左上一个小实心点，一条虚线斜着落在塔顶。补的是「点对点」这层意思： 工具间不是孤立的点，是链路的一端；虚线也正好接住山脊的斜势。 它比 C 更直接地占住那个角，代价是 32 px 下只剩一个点和一小截虚线。

节点 (14,15) r 2.2 · 虚线至 (52.6,30.2) · stroke 1.5
ERIDGE / 最含蓄

远山 / 左峰后面再加一道脊

用更细的线在左峰后画一道远山，把「大龙山」从一座山扩成山脉，同时压住左上。 语义最顺，但 32 px 下会变成一撮折线；而且容易显得像随手画的背景。

x 3–41 / y 31–51 · stroke 2.1 · opacity 0.7
FREGISTER / 最克制

角标 / 图纸登记角

左上双折角，像制图胶片或印版的对位线。它不描述任何东西，只声明「这是一张图」。 好处是 32 px 仍成立，坏处是只有一个角时略像 UI 裁剪框；可考虑右下再加一个极轻的角。

外 16 / 内 7 · stroke 2 + 1.4
GORBIT / 最大胆

轨道 / 同心的第三道大弧

不画新东西，只把已有的「弧」语言放大到 r 30，在左上露出一小段轨道和一个卫星点。 山是地面站，弧是覆盖，轨道是空间段——三层通信叙事一次说清。风险是容易读成一道乱入的光晕。

r 30 · 125°–170° · stroke 1.5 · 点 r 2.1
FIRST CHOICE

D · 链路节点

最直接地补掉左上角的空，而且补的是信息不是装饰：远端点、虚线、本站，把「通信」这层 说完整。建议实心点 r 2.2、虚线 3/3.4、线宽 1.5；32 px 以下可省略虚线，只留点。

SECOND CHOICE

C · 标高线

如果不想再加一个「点」，这是最克制的一笔：一条测量基准线，不抢山、不抢信号，还在 32 px 下保得住。建议线宽 1.6、虚线 3/3.2、端竖用方头，不透明度 0.85。

KEEP AS OPTION

B · 风线

已有稿，语义和完成度都够，只是「天气感」比「工程感」强。若最终选它，建议把三道线的 间距再收紧 1 px、线宽降到 2.2，让它退到背景层，别和信号弧抢粗细。
