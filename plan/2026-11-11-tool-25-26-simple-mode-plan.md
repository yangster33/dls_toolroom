# 工具 25 / 26 简易 / 专业双模式方案（简版）

> 分支：各自从 `master` 切（`feat/tool-25-simple-mode`、`feat/tool-26-simple-mode`）
> 日期：2026-11-11
> 状态：待实施（§2 三处口径待确认）
> 前置：工具 25/26 的透明度改造已完成，且用的是 `src/tools/shared` 里的共用模块

## 1. 目标

给工具 25（通信直流电源柜）和 26（机房空调制冷量）各加「简易 / 专业」双模式：

- 默认简易，只暴露核心输入，其余按假定值参与计算；
- 固定值在页面常驻可见（`AssumptionCard`），计算书与复制报告一并注明；
- 专业模式的字段、默认值与结果保持不变；
- **与 23/24 不同的是**：组件、组合式、样式都已存在，本轮只写两个 `createSimpleInput()`
  和页面的条件渲染，不再复制任何模板或 CSS。

## 2. 待确认口径

| # | 决策项 | 建议 | 备选 |
|---|---|---|---|
| 1 | 默认模式 | 简易（与 23/24 一致） | 保持专业默认，仅提供开关 |
| 2 | 简易模式的「假定」粒度 | 只固定厂家/规范类参数（模块降额、柜体尺寸、效率、余量） | 连负荷相关也固定（不推荐，会让结果失真） |
| 3 | 26 的面积指标 | 400 W/m²（通信机房经验值）随房间类型取预设 | 不提供面积法，只保留详细法 |

## 3. 共用部分（一次定义，两个工具都用）

- 状态：`useUiMode({ storageKey, createSimple, createDefault, getForm, setForm })`
  - `dls.dc-power-cabinet.ui-mode.v1`、`dls.hvac-cooling.ui-mode.v1`
- 组件：`ModeSwitch`、`AssumptionCard`、`ResultStrip`（`badge="简易"`）、`CalcBook`（`mode-note`）、`ParamDocs`
- 样式：根节点 `selection-tool calc-trace`，`<script>` 里 import 两个 css
- 报告：在标题行后插一行 `模式：简易（……）`，专业模式不加
- 计算书：本轮不改来源标签（与 23 一致），固定值仍按实际代入值显示

## 6. 明确不做（与 23/24 一致）

| 项 | 原因 |
|---|---|
| 改引擎公式 / clamp / `createDefaultInput()` | 简易模式只是输入值组合 |
| 独立简易路由 / 新工具条目 | 结果卡与计算书会分叉 |
| 表单字段持久化 | 只持久化模式 |
| 逐符号标「默认」来源 | 用假定卡 + 模式行覆盖 |
| 计算书域逻辑抽到 shared | 25/26 的步骤与校核是域内知识，留在各自目录 |
| 页面 e2e | 沿用引擎单测 + 截图 |

## 8. 测试策略

每个工具新增 3 条引擎单测：

1. `createSimpleInput()` 字段断言（25：降额 0.9 / 柜体 2000×600×600 / 三相 380 V；26：面积指标 400 / 显热比 0.9 / 机组自动）；
2. 简易默认结果锚点：25 默认 -48 V / 200 A / 500 Ah → 模块数、柜数、断路器；26 默认 100 m² 面积法 → 总冷负荷、推荐容量；
3. 专业默认回归：`createDefaultInput()` 与现有用例结果不变。

页面手工验证：模式持久化、切换保留、重置按模式、假定卡行数（26 两种计算方式）、报告模式行、1440×900 截图。

门禁：`type-check`、`lint:check`、`test:unit`、`build-only`。

## 10. 风险

- **默认模式改动**：首次进入从全字段变简易；不接受时把默认值设为 `professional`（一行）。
- **25 的柜体/降额是厂家相关**：简易值只适合方案初选，假定卡与提示必须写清，不能当成定型参数。
- **26 面积法误差大**：400 W/m² 只适用通信机房粗估；设备机房、高密度机房必须用详细法。
- **两轮改造的先后**：必须「先 rebase + 透明度（用共用模块）→ 再简易模式」，否则页面要改两遍。
- **与 23/24 的模式语义一致**：切回简易会恢复假定值，toast 与假定卡要讲清。
